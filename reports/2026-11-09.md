## Biweekly new-tool and Azure opportunity scan

#### 1. Microsoft Foundry Decisions API — Pilot now

- **Why relevant:** Consulting and Corporate Solutions teams often need routing, classification, or rubric scores from text. The Decisions API returns typed answers, so code does not have to parse prose.
- **Problem it could solve:** It replaces prompt-and-parse routing with three answer types: `predicate` (yes/no with a probability), `choice` (one option from a fixed list), and `score` (position on an ordered rubric) [Foundry October 2026 update](https://devblogs.microsoft.com/foundry/whats-new-in-microsoft-foundry-october-2026/).
- **Maturity and momentum:** Generally available since 22 Oct 2026. It supports `gpt-6-luna`, and the rollout excluded East US 2 at the time of writing [Foundry October 2026 update](https://devblogs.microsoft.com/foundry/whats-new-in-microsoft-foundry-october-2026/). The GA announcement is [here](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/azure-openai-decisions-api-now-generally-available-in-microsoft-foundry/4567265).
- **Adoption effort and risks:** Needs an Azure resource, a model deployment, and Entra ID auth. The vendor's demo shows one case, not accuracy. Probabilities must be checked against your own labeled data. Client-data residency and approval are required. Refusals must go to a human.
- **First pilot:** Label about 200 anonymized or synthetic requests from a past project. Run `predicate` and `choice` questions. Record false positives and false negatives. Set the review threshold by the cost of each error. Do not connect any automatic action until the error table is reviewed. Reference: [Decisions how-to](https://learn.microsoft.com/azure/foundry/openai/how-to/decisions).

#### 2. Polars 2.x — Evaluate

- **Why relevant:** Python data pipelines that hit memory limits or run slowly on large files.
- **Problem it could solve:** Polars 2.0 made the streaming engine the default for `collect()`, and enabled out-of-core spill-to-disk [Polars 2.0 release](https://pola.rs/posts/release-polars-2/). Polars 2.1 added out-of-core group-by, recursive SQL, and Iceberg catalog support [Polars 2.1 announcement](https://pola.rs/posts/polars-2-1-changelog/).
- **Maturity and momentum:** Polars 2.1.0 was published to PyPI on 25 Oct 2026 with provenance from GitHub Actions [PyPI](https://pypi.org/project/polars/). The 2.0 release was on 6 Oct 2026. The R bindings exist, but I did not check the r-polars version.
- **Adoption effort and risks:**
  - Row order is no longer guaranteed for `join`, `group_by`, and `unpivot` unless `maintain_order=True`. Order-dependent code can produce silent differences.
  - 2.1 makes mixed string and numeric arithmetic in eager mode raise an error, and drops Python 3.10 [Polars 2.1 announcement](https://pola.rs/posts/polars-2-1-changelog/).
  - The 2.1 release lists several "wrong results" fixes (for example, unsigned Parquet statistics and Decimal-to-integer casts). Exposure in existing pipelines is unknown.
- **First pilot:** Choose one pipeline that is slow or runs out of memory. Run the old and new versions side by side. Compare outputs with and without row order. Set `POLARS_OOC_MEMORY_BUDGET_MB` to test spilling. Record run time and peak memory.

#### 3. Copilot code review for Azure Repos — Evaluate

- **Why relevant:** Teams that use Azure Repos but not GitHub can get AI review on pull requests without migrating.
- **Problem it could solve:** Early feedback on potential bugs, code quality, and maintainability in pull requests [Azure Repos sprint 275](https://learn.microsoft.com/en-us/azure/devops/release-notes/2026/repos/sprint-275-update).
- **Maturity and momentum:** Limited public preview since sprint 275 (June 2026). Enabling it requires an approved sign-up [Azure Repos sprint 275](https://learn.microsoft.com/en-us/azure/devops/release-notes/2026/repos/sprint-275-update).
- **Adoption effort and risks:** Preview features may change. AI comments can be wrong. It does not replace human approval. Check data-handling terms with IT or security before using it on client code.
- **First pilot:** Enable it on two repositories: one Python API and one R analytics package. Over four weeks, track accepted and dismissed comments and any real defects it found that humans missed.

#### 4. Foundry Local 2.2.1 — Evaluate

- **Why relevant:** On-device inference for confidential client data where cloud calls are not allowed.
- **Problem it could solve:** Local model serving with better tool calling, a v2 catalog, and removal of corrupted caches [Foundry October 2026 update](https://devblogs.microsoft.com/foundry/whats-new-in-microsoft-foundry-october-2026/).
- **Maturity and momentum:** SDK/runtime 2.2.1 shipped on 23 Oct 2026. The CLI 0.12.1 shipped the same day as a separate public preview. Keep the two versions apart when you plan an upgrade.
- **Adoption effort and risks:** GPU use needs separately installed CUDA and cuDNN runtimes. The required CUDA major differs between x64 and ARM64. Windows x64 needs an `AddDllDirectory` step. Output quality for your tasks is unknown.
- **First pilot:** Use one known model on one developer workstation. Confirm it loads on the intended execution provider. Test tool-call validation and cancellation with about 50 non-sensitive prompts.

#### 5. Foundry Browser Automation — Watch

- **Why relevant:** Some client-facing tools exist only as web portals without APIs.
- **Problem it could solve:** Agents can run browser workflows through a Playwright Workspace and a Toolbox MCP endpoint. It went GA on 19 Oct 2026 [Foundry October 2026 update](https://devblogs.microsoft.com/foundry/whats-new-in-microsoft-foundry-october-2026/) and [Browser Automation GA](https://devblogs.microsoft.com/foundry/browser-automation-tool-ga/).
- **Why Watch:** Web pages are untrusted input and could carry prompt injection. Sensitive-content protection for traces is still preview. Security controls for client data are not yet proven.
- **If approved later:** Start with a read-only lookup on a site you control. Compare returned fields with the source. Test a page that contains injected instructions. Require human approval before any write.
