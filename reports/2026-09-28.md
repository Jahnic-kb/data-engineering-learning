### Biweekly new-tool and Azure opportunity scan

#### 1. Azure Pipelines — container jobs and Node task handlers

**[HIGH FEATURE | pipeline failures and safer defaults] Preflight container jobs and legacy task handlers**

- **What changed:** Azure Pipelines agent **5.279.0** no longer maps `/var/run/docker.sock` into Linux container jobs by default. Jobs that need access to the host Docker daemon must explicitly set `mapDockerSocket: true`. Separately, Microsoft says Node.js 6, 10, and 16 task handlers will be removed on **2026-11-24**; the newer-runner test option can help identify incompatible tasks, but compatibility is not guaranteed.
- **Potential impact:** The new socket default could break container jobs that rely on the host Docker daemon. The upcoming handler removal could make affected pipeline tasks fail. These are possible risks; Kienbaum’s pipeline configuration is unknown.
- **Exposure:** Check agent versions, Linux container jobs, Docker-in-Docker or host-daemon usage, and custom or extension tasks. The documented change begins at agent 5.279.0; exposure at Kienbaum is unknown.
- **Maturity and momentum:** These are documented Azure Pipelines service/agent changes, with the task-handler removal scheduled for November. The changes are operationally relevant whether or not Kienbaum adopts a new tool.
- **Adoption effort and risks:** Low effort to inventory and test; allow time to validate task compatibility and Docker access without changing production pipelines prematurely.
- **How to benefit:** Run affected pipelines in a test environment. Explicitly enable `mapDockerSocket` only for jobs that require it, and test pipelines using older task handlers before the removal date.
- **Sources:** [Azure DevOps Sprint 279 update](https://learn.microsoft.com/en-us/azure/devops/release-notes/2026/sprint-279-update); [Azure Pipelines Node.js runners](https://learn.microsoft.com/en-us/azure/devops/pipelines/agents/nodejs-runners).
- **Recommendation: Pilot now**

#### 2. MarkItDown 0.1.8 — document and data conversion

**[HIGH BUGFIX | dropped or misread data] Check CSV and archive ingestion fixes**

- **What changed:** Microsoft’s MarkItDown **0.1.8**, released **2026-09-21**, includes fixes for CSV parsing that preserve columns using the widest row, CR-only line endings, UTF-8 BOMs, and duplicate filenames in ZIP archives.
- **Potential impact:** Where these input formats occur, earlier conversion behavior could omit columns or fail to preserve file content. That could affect downstream analysis or reporting; Kienbaum usage and exposure are unknown.
- **Exposure:** The release notes do not state a complete affected-version range. The fixes are present in 0.1.8; check Python lockfiles and conversion workflows to determine whether MarkItDown is used.
- **Maturity and momentum:** This is a versioned release of Microsoft’s open-source conversion project. The release date is within the 21-day scan window; release activity alone does not establish Kienbaum adoption.
- **Adoption effort and risks:** A targeted fixture test is low effort. Validate converted output against source files before relying on an upgrade for production ingestion.
- **How to benefit:** Test representative CSVs with uneven row widths, CR-only line endings, BOMs, and ZIP archives with duplicate filenames. If the output is correct, consider updating the pinned version.
- **Sources:** [MarkItDown 0.1.8 release](https://github.com/microsoft/markitdown/releases/tag/v0.1.8).
- **Recommendation: Evaluate**

#### 3. renv 1.2.4 — R dependency management

**[HIGH BUGFIX | reproducibility and package integrity] Verify version-pinned installs and shared caches**

- **What changed:** **renv 1.2.4**, released **2026-08-03**, fixes behavior where `renv::use()` could fail to honor an explicitly requested package version when pak was enabled. It also avoids upgrading already-compatible transitive dependencies and rejects corrupted cache entries containing the wrong package, among other dependency-resolution and locking improvements.
- **Potential impact:** If affected workflows use pak, pinned package requests, or shared caches, these issues could undermine reproducibility or package integrity. Kienbaum’s renv usage and exposure are unknown.
- **Exposure:** The release notes do not provide a complete affected-version range. Check `renv.lock`, CI restore/install commands, pak configuration, and cache setup before upgrading.
- **Maturity and momentum:** This is a versioned renv release within the 90-day trend window. Its changes are relevant to reproducible R environments and shared-cache workflows.
- **Adoption effort and risks:** Test in a branch or CI environment first, especially where multiple projects share a package cache. Avoid treating an upgrade alone as proof that existing lockfiles restore identically.
- **How to benefit:** In a test project, request a specific package version with pak enabled, restore from the lockfile, and exercise the configured cache workflow. Compare installed versions and package integrity before and after moving to 1.2.4.
- **Sources:** [renv 1.2.4 release](https://github.com/rstudio/renv/releases/tag/v1.2.4).
- **Recommendation: Evaluate**
